# ArkGate

火山方舟（Volcengine Ark）**多账号负载均衡 + OpenAI 兼容网关**。

把火山复杂的 `/api/v3` 协议转成标准 OpenAI 兼容格式，解决两大痛点：

1. **多账号负载均衡**——把十几个火山账号的 API Key 放进池子里，网关在请求时按
   **平滑加权轮询 + 熔断 + 限流** 自动选一个账号，对下游完全透明。
2. **易读模型名 ↔ ep-xxx 映射**——火山每个账号的推理接入点都是 `ep-` 开头的一串
   无意义随机字符，且账号间各不相同。本网关维护「**账号 × 易读模型名 → 真实 ep**」
   的映射表，下游用 `doubao-seed-1-6` 这样的名字调用，网关调用火山时自动换回
   `ep-xxxx`。

> 纯 Go 编写，单二进制、零外部依赖（SQLite 内置、前端 `go:embed` 内嵌），开箱即用。

---

## 特性

- **OpenAI 兼容**：`POST /v1/chat/completions`（流式/非流式）、`GET /v1/models`，
  可直接把 `base_url` 指到本网关，用任意 OpenAI SDK 调用。
- **熔断 + 限流（叶节点级）**：限流与熔断只发生在 ep 接入点上——每个接入点可独立配置
  **并发 / RPM / TPM**；连续失败自动熔断该接入点（指数退避冷却）并切到别的叶子。
  账号本身不单独限流、不单独熔断，只做 active/disabled 开关。
- **子 Key 体系**：真实火山 Key 只存在服务端（加密落盘），下发给客户端的是
  `sk-xxx` 子 Key。子 Key 可限制可访问模型、可访问账号、当日 Token 限额。请求时
  网关用选中的账号真实 Key 替换子 Key，真正请求火山。
- **模型映射**：易读名 → ep-xxx 的一对多映射（按账号维度），支持不映射时透传
  `ep-` 真实 ID。
- **用量统计（子 Key 维度）**：不向火山上游同步，含请求次数、token、耗时、错误；
  账号与接入点（元组）也分别累计，熔断/限流状态实时可见。
- **内嵌 Web 管理界面**：Arco Design 风格，总览 / 账号 / 模型映射 / 子 Key / 日志 /
  使用说明。

## 快速开始

```bash
# 构建
go build -o arkgate .

# 运行
./arkgate
```

首次运行自动生成管理访问令牌并打印到控制台，登录 Web 界面时使用。
默认监听 `0.0.0.0:8002`，端口被占用时自动向后递增直到找到可用端口。

运行时数据（SQLite 数据库 + 加密密钥）保存在可执行文件同级目录，不污染系统其它位置。
可通过 `ARKGATE_DATA_DIR` 环境变量显式覆盖。

### 环境变量

| 变量 | 说明 | 默认值 |
|---|---|---|
| `ARKGATE_ADDR` | 监听地址 | `0.0.0.0:8002`（被占用时自动向后递增） |
| `ARKGATE_BASE_URL` | 火山 Base URL | `https://ark.cn-beijing.volces.com/api/v3` |
| `ARKGATE_DATA_DIR` | 数据目录（sqlite + secret.key） | 可执行文件同级目录 |
| `ARKGATE_SECRET` | 固定加密主密钥（可选，不设则自动生成） | — |

## 使用流程

1. **添加账号**：在「火山账号」填入账号名称与火山方舟长效 API Key（从
   [API Key 管理](https://console.volcengine.com/ark/region:cn-beijing/apiKey) 获取）。
2. **建模型目录**：在「模型映射」新建易读模型名（如 `doubao-seed-1-6`）。
3. **添加映射**：为「账号 × 模型」填写真实接入点 `ep-xxx`（或 Model ID）。
4. **建子 Key**：创建一张 `sk-xxx`，可选限制模型/账号/当日 Token 限额。
5. **调用**：把客户端 `base_url` 指向本网关，用子 Key 作为 API Key（模型名填易读名）：

```bash
curl http://localhost:8002/v1/chat/completions \
  -H "Authorization: Bearer sk-你的子Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "doubao-seed-1-6",
    "messages": [{"role": "user", "content": "你好"}],
    "stream": false
  }'
```

多数 OpenAI SDK 只需改两处：`base_url` 与 `api_key`（换成子 Key）。

> 流程里第 3 步的「添加映射」同时是元组级流控的配置点：每个 `(账号 × 模型)` 映射
> 可独立设置权重 / 并发 / RPM / TPM。网关对某个模型做路由时，只在该模型的
> **可用元组集合**里选（未熔断、未限流、账号启用），权重可作为元组权重或回落到账号权重。

## 流控与路由模型

采用**树状结构**：

```
账号（父节点）——只有 active/disabled 开关 + 统计聚合，不单独限流、不单独熔断
   ├── ep 接入点（叶节点）——限流（并发/RPM/TPM）与熔断只在这一层
   ├── ep 接入点（叶节点）
   └── ...
```

- **路由**：客户端用子 Key 鉴权 + 指定易读模型名 → 网关收集该模型下所有可用叶节点
  （账号启用、叶子未熔断、未超限）→ 平滑加权轮询（权重：`叶.weight > 账号.weight > 1`）
  → 命中 `(账号, ep)` → 用账号真实 Key 替换子 Key、把 `model` 换成真实 `ep-xxx` 后转发火山。
- **限流**：并发 / RPM / TPM 全部在**叶节点（ep 接入点）**上生效，一个账号的不同接入点互不影响。
- **熔断**：只在叶节点上发生——某接入点连续失败达标即熔断该接入点（自动切到别的叶子）。
- **统计视角**：叶节点各自累计，账号作为父节点自动聚合其下所有接入点的统计，
  管理员可「从账号视角」看汇总，也可下钻到单个 ep。
- **请求重试**：转发失败把当前叶节点加入本请求排除集，切下一个叶子重试，最多 3 次。

## 负载均衡策略

- **平滑加权轮询**：权重越大的叶节点分到越多请求（叶节点可覆盖账号默认权重）。
- **熔断**：某接入点连续失败 5 次即熔断，冷却时长按失败次数指数退避（1s → 最长 60s）。
- **限流**：命中并发 / RPM / TPM 的叶节点在窗口期内不再被选中。
- **请求重试**：转发失败自动排除当前叶节点并切下一个，最多重试 3 次。

## 并发模型

Go `net/http` 每个请求一个 goroutine，转发链路全程无全局串行锁：

- 元组/账号运行态（并发数、连续失败、熔断时间、RPM/TPM 窗口）用**原子操作 + 细粒度锁**维护；
- 负载均衡 `Select` 走无阻塞快照 + 短临界区；
- 用量统计与日志写库经**有界 channel 异步落盘**，不阻塞请求热路径。

## 数据安全

- 火山账号 API Key 用 **AES-256-GCM** 加密后落盘（主密钥存 `~/.arkgate/secret.key`，
  权限 `0600`），任何 API 响应都不回传明文；
- 子 Key 明文只存一份（用于展示给用户复制），鉴权按 SHA-256 哈希匹配；
- 管理 API 采用访问令牌鉴权（Bearer Token），令牌哈希存储。

## 目录结构

```
arkgate/
├── main.go                 # 入口：装配 + 路由（/v1、/api、/ 内嵌前端）
├── internal/
│   ├── config/             # 环境变量配置
│   ├── secure/             # AES-256-GCM 加解密
│   ├── model/              # 数据模型 + 滑动窗口
│   ├── store/              # SQLite 持久化（自动建表迁移）
│   ├── balancer/           # 加权轮询 + 熔断 + 限流
│   ├── upstream/           # 火山 v3 客户端（透传 + 字段对齐）
│   ├── gateway/            # /v1 OpenAI 兼容转发层
│   └── admin/              # /api 管理接口 + 令牌鉴权
└── web/                    # 内嵌单页前端（go:embed）
    ├── index.html
    ├── style.css           # Arco 设计变量与组件
    └── app.js              # 无框架 SPA
```

## 关于 /v1/responses

火山原生有 Responses API（`/api/v3/responses`），但其 OpenAtom 语义复杂、与主流
OpenAI SDK 生态的兼容度不高。本网关**优先实现 `/v1/chat/completions`** 作为主路径；
`/v1/responses` 暂返回 `501`，如后续需要再补。
