## 实施计划

1. **完善映射级请求头数据链路**
   - 在 `Endpoint` 叶节点增加请求头字段，因为映射、限流、熔断和实际上游选择都以 Endpoint 为粒度。
   - 增加数据库迁移，并同步更新查询、扫描、创建、修改和缓存热加载逻辑。
   - 管理 API 直接保存规范化后的 header map，不在后端持久化“预设名称”。
   - 对请求头名称和值做校验，拒绝 CR/LF 注入，并禁止覆盖 `Authorization`、`Host`、`Content-Length` 等由网关控制的头。

2. **把请求头应用到所有上游调用路径**
   - 在最终选中 Endpoint 后构造上游请求并注入其专属请求头。
   - 覆盖 OpenAI Chat、OpenAI Responses、Anthropic Messages，以及重试和 fallback 路径。
   - 保证 fallback 切换 Endpoint 时请求头也随之切换，不复用上一次命中的映射配置。

3. **增加管理前端配置能力**
   - 在映射编辑界面增加请求头编辑器。
   - 提供“空白”和“Claude Code”预设，预设只负责填充表单，最终仍保存实际键值。
   - 空白预设表示不添加任何额外请求头。
   - Hermes 暂不内置不可靠的固定预设，但可通过自定义请求头完整配置。
   - Claude Code 预设值仅采用可验证来源，不根据名称猜��测。

4. **补齐 Responses 与 Anthropic 的协议转换**
   - 移除 `/v1/responses` 对 Anthropic 上游的硬拒绝，接入与现有 Chat/Anthropic 转换一致的选择、重试、计量和错误处理链路。
   - 实现 Responses 输入到 Anthropic Messages 的转换，包括文本、消息项、function tools、function call 与 function output 配对。
   - 实现 Anthropic 非流式响应到 Responses 输出结构的转换，包括文本、工具调用、停止原因和 usage。
   - 实现 Anthropic SSE 到 Responses SSE 生命周期事件的转换，包括 created、in_progress、output item、content delta、completed 和 failed。
   - 同时修正当前错误文案只提示 `/v1/chat/completions`、遗漏 `/v1/messages` 的问题。

5. **测试与回归验证**
   - 增加 Endpoint 请求头的数据库、管理 API 和热更新测试。
   - 使用 `httptest.Server` 验证 User-Agent、自定义头、不同映射隔离、fallback 后切换、安全头保护和 CR/LF 拒绝。
   - 覆盖 Chat、Responses、Messages 三种调用路径。
   - 扩展协议测试，覆盖多工具调用、分片参数、纯工具响应、交错内容块、stop reason、usage、未知流事件、失败事件和客户端取消。
   - 运行 Go 全量测试及仓库现有前端检查流程，确认无回归。
